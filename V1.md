# Sillo v1 — the context rewrite

Branch: `v1`. **No backward compatibility.** `Request`, the `Response` manager
and the `Responder` builder are gone, not shimmed.

## The shape

```python
from sillo import SilloApp, HttpContext, json, Depend, Query

app = SilloApp()

@app.get("/users/{id:int}")
def show(ctx: HttpContext, id: int):
    return json({"id": id})

@app.get("/search")
async def search(ctx: HttpContext, db=Depend(get_db), q=Query("")):
    return json(await db.find(q))

@app.websocket("/room/{name}")
async def room(ctx: WebSocketContext, name: str):
    await ctx.accept()
    await ctx.send_json({"room": name})
```

One argument: the context. Path parameters, dependencies and validation markers
follow it, bound by name exactly as before.

## Classes

```
BaseContext                     the shared ASGI-connection surface
  HttpContext                   an HTTP request; the argument to HTTP handlers
  WebSocketContext              a socket; the argument to WebSocket handlers
```

`BaseContext` carries `scope`, `headers`, `cookies`, `path_params`,
`query_params`, `state`, `user`, `client`, `app`, `url_for`. `HttpContext` adds
`method`, `await ctx.json`, `await ctx.body`, `await ctx.form`, `ctx.files`,
`ctx.validated_data`. `WebSocketContext` adds `accept`, `send`, `receive`,
`send_json`, `receive_json`, `close`, `iter_*`.

Defined in `sillo/core/http/context.py`; `sillo/core/http/request.py` is gone.

## Responses

Everything lives in **`sillo.responses`**, and every name is re-exported from
`sillo` — `from sillo import json` and `from sillo.responses import json` are
the same function. Import from the module when the file also needs the stdlib
`json`/`html` or the `file` builtin.

| | |
|---|---|
| bodies | `json` `text` `html` `xml` `raw` `empty` |
| status shorthands | `created` `accepted` `no_content` |
| redirects | `redirect` `permanent_redirect` `see_other` `temporary_redirect` |
| files | `file` `download` |
| streaming | `stream` `ndjson` `sse` |
| pagination | `paginate` `apaginate` — these take `ctx` first, for the URL and query |
| stopping early | `abort` `not_found` — these raise instead of returning |

The response classes (`BaseResponse`, `JSONResponse`, …) are re-exported there
too, for a handler that wants to construct one directly or subclass it.

Each builder returns a `BaseResponse` subclass, which is also where the
chainable half lives — `status`, `cache`, `no_cache`, `set_header`,
`set_headers`, `set_cookie`, `set_cookies`, `set_permanent_cookie`,
`delete_cookie`, `set_body`, `has_header`, `content_length`, `add_csp_header` —
each returning `self`:

```python
return json(payload, status_code=201).set_cookie("seen", "1").cache(max_age=60)
```

## Middleware

```python
class RequireLogin(BaseMiddleware):
    async def dispatch(self, ctx, call_next):
        if ctx.user is None:
            return redirect("/login")      # stop here
        response = await call_next()       # or continue
        response.set_header("x-checked", "1")
        return response
```

One hook. Returning a response ends the chain; awaiting `call_next` continues
and hands back what the rest produced. The `process_request` /
`process_response` pair is gone — the post-phase is whatever follows the await.

Every built-in was rewritten: CORS, CSRF, session, auth, rate limit, shield,
templating, normalize, accepts, etag, request-id.

## `sillo._internals` is gone

It held three unrelated things behind one private name, and every caller had to
reach through `sillo._internals._middleware`. Each moved to where it belongs,
with no functional change:

| was | is |
|---|---|
| `_internals/_middleware.py` | `middleware/define.py` — `DefineMiddleware`, `wrap_middleware` |
| | `middleware/bridge.py` — `ASGIRequestResponseBridge`, `_CachedRequest`, `_StreamingResponse` |
| `_internals/lazy.py` | `helpers/lazy.py` |
| `_internals/registry.py` | `helpers/registry.py` |

The 549-line middleware module split along the seam that was already there:
declaring a middleware (`define`) versus mounting one above an ASGI application
(`bridge`). `define` imports `bridge`, one direction.

`define` and `bridge` stay out of `sillo/middleware/__init__.py` on purpose —
the package init re-exports the security middleware, and importing the plumbing
from there rather than by module path is what made that a cycle once before.

## Everything else that moved

- Templating: `render(..., ctx=ctx)`, and the template variable it injects is
  `{{ ctx }}`. `TemplateContextMiddleware` puts the same name on
  `ctx.state.template_context`. A template written against `{{ request }}` has
  to be updated.
- Exception handlers: `(ctx, exc)`.
- Auth gates: `guard(ctx)`; `useAuth` hooks take `(ctx)`.
- Auth backends: `handle_exception(ctx, exc)`.
- `StaticFiles(custom_404_handler=...)`: the handler takes `(ctx)`.
- `RateLimitConfig(on_exceed=...)`: the callable takes `(ctx, result)`.
- Redirect-by-route-name: `redirect(ctx.url_for("name", **params))`.

## Naming

`json`, `text`, `html` and `file` shadow stdlib modules and builtins. Where a
module needs both, either import the builder under an alias — see
`sillo/core/error/handler.py` (`html as html_response`) and
`sillo/admin/routes.py` (`json as json_response`) — or take the module and
qualify: `from sillo import responses` then `responses.json(...)`. A handler or
local named after a builder shadows it the same way; the tests hit this three
times.

## No `request` left over

The cutover renamed the parameter to `ctx` and then rebound it -- `request =
ctx` on the first line of thirteen `dispatch` methods -- so the bodies did not
have to change. That alias is gone; the bodies use `ctx`. `AcceptsInfo.request`
is `AcceptsInfo.ctx` for the same reason.

Two bugs this turned up, both from the same sweep:

- WebSocket routes read path parameters from `scope["path_params"]`, which the
  router never writes -- it uses `scope["route_params"]`. The keyword arguments
  the code meant to pass were always empty. Path parameters now bind as kwargs
  on a WebSocket route exactly as on an HTTP one, so a handler declares them.
  `WebSocketConsumer.as_route` absorbs them rather than forwarding, since the
  consumer hooks have no parameter to bind them to.
- The rename hit English prose in docstrings and log lines, turning "a WebSocket
  route" into "a WebSocketContext route". Reverted wherever the word was never
  the class name.

## Not done

  Inertia's `_endpoint_signature` fakes a `(request, response, *rest)`
  signature and has to be rewritten against the context.
- `sillo-start` templates generate old-style handlers.

# Sillo v1 — the context rewrite

Branch: `v1`. **No backward compatibility.** `Request`, the `Response` manager
and the `Responder` builder are gone, not shimmed.

## The shape

```python
from sillo import SilloApp, HttpContext, json, Depend, Query

app = SilloApp()

@app.get("/users/{id:int}")
def show(ctx: HttpContext, id: int):
    return json({"id": id})

@app.get("/search")
async def search(ctx: HttpContext, db=Depend(get_db), q=Query("")):
    return json(await db.find(q))

@app.websocket("/room/{name}")
async def room(ctx: WebSocketContext, name: str):
    await ctx.accept()
    await ctx.send_json({"room": name})
```

One argument: the context. Path parameters, dependencies and validation markers
follow it, bound by name exactly as before.

## Classes

```
BaseContext                     the shared ASGI-connection surface
  HttpContext                   an HTTP request; the argument to HTTP handlers
  WebSocketContext              a socket; the argument to WebSocket handlers
```

`BaseContext` carries `scope`, `headers`, `cookies`, `path_params`,
`query_params`, `state`, `user`, `client`, `app`, `url_for`. `HttpContext` adds
`method`, `await ctx.json`, `await ctx.body`, `await ctx.form`, `ctx.files`,
`ctx.validated_data`. `WebSocketContext` adds `accept`, `send`, `receive`,
`send_json`, `receive_json`, `close`, `iter_*`.

Defined in `sillo/core/http/context.py`; `sillo/core/http/request.py` is gone.

## Responses

Free functions in `sillo/core/http/shortcuts.py`, exported from `sillo`:

| | |
|---|---|
| `json` `text` `html` `empty` | bodies |
| `redirect` | 302 by default |
| `file` `download` | from disk, with range support |
| `stream` `sse` | chunked and Server-Sent Events |
| `paginate` `apaginate` | take `ctx` first, for the URL and query |
| `abort` `not_found` | raise instead of returning |

Each returns a `BaseResponse` subclass, which is also where the chainable half
now lives — `status`, `cache`, `no_cache`, `set_header`, `set_headers`,
`set_cookie`, `set_cookies`, `set_permanent_cookie`, `delete_cookie`,
`set_body`, `has_header`, `content_length`, `add_csp_header` — each returning
`self`:

```python
return json(payload, status_code=201).set_cookie("seen", "1").cache(max_age=60)
```

## Middleware

```python
class RequireLogin(BaseMiddleware):
    async def dispatch(self, ctx, call_next):
        if ctx.user is None:
            return redirect("/login")      # stop here
        response = await call_next()       # or continue
        response.set_header("x-checked", "1")
        return response
```

One hook. Returning a response ends the chain; awaiting `call_next` continues
and hands back what the rest produced. The `process_request` /
`process_response` pair is gone — the post-phase is whatever follows the await.

Every built-in was rewritten: CORS, CSRF, session, auth, rate limit, shield,
templating, normalize, accepts, etag, request-id.

## Everything else that moved

- Exception handlers: `(ctx, exc)`.
- Auth gates: `guard(ctx)`; `useAuth` hooks take `(ctx)`.
- Auth backends: `handle_exception(ctx, exc)`.
- `StaticFiles(custom_404_handler=...)`: the handler takes `(ctx)`.
- `RateLimitConfig(on_exceed=...)`: the callable takes `(ctx, result)`.
- Redirect-by-route-name: `redirect(ctx.url_for("name", **params))`.

## Naming

`json`, `text`, `html` and `file` shadow stdlib modules and builtins. Where a
module needs both, import the builder under an alias — see
`sillo/core/error/handler.py` (`html as html_response`) and
`sillo/admin/routes.py` (`json as json_response`). A handler or local named
after a builder shadows it the same way; the tests hit this three times.
